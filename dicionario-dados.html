Dicionário de Dados

Projeto acadêmico de banco de dados para a Cinthiê Confeitaria. Este documento descreve as entidades, atributos, tipos de dados, chaves e regras principais utilizadas no modelo.

Sistema: Controle de pedidos da confeitaria
Modelo: DER conceitual com apoio ao modelo lógico
Canais: WhatsApp, balcão e plataformas parceiras
Cliente Funcionário Produto Pedido Item_Pedido Pagamento Plataforma Regras Gerais

Entidade: Cliente

Atributo Tipo sugerido Chave Obrigatório Descrição
id_cliente INT PK Sim Identificador único do cliente.
nome VARCHAR(100) - Sim Nome completo ou nome informado pelo cliente.
telefone VARCHAR(20) - Sim Telefone utilizado para contato, principalmente em pedidos via WhatsApp.

Entidade: Funcionário

Atributo Tipo sugerido Chave Obrigatório Descrição
id_funcionario INT PK Sim Identificador único do funcionário.
nome VARCHAR(100) - Sim Nome do funcionário responsável pelo atendimento ou registro do pedido.
funcao VARCHAR(50) - Sim Função exercida pelo funcionário dentro da confeitaria.

Entidade: Produto

Atributo Tipo sugerido Chave Obrigatório Descrição
id_produto INT PK Sim Identificador único do produto vendido pela confeitaria.
nome VARCHAR(100) - Sim Nome comercial do produto.
preco DECIMAL(10,2) - Sim Preço padrão do produto.
descricao VARCHAR(255) - Não Descrição resumida do produto, como sabor, tamanho ou observações relevantes.

Entidade: Pedido

Atributo Tipo sugerido Chave Obrigatório Descrição
id_pedido INT PK Sim Identificador único do pedido.
data DATE - Sim Data em que o pedido foi realizado.
status VARCHAR(30) - Sim Situação atual do pedido, como pendente, em preparo, finalizado ou cancelado.
canal_pedido VARCHAR(30) - Sim Canal de origem do pedido. Exemplos: WhatsApp, balcão ou plataforma.
id_cliente INT FK Sim Identifica o cliente que realizou o pedido.
id_funcionario INT FK Sim Identifica o funcionário responsável pelo registro ou atendimento do pedido.

Entidade: Item_Pedido

Atributo Tipo sugerido Chave Obrigatório Descrição
id_item INT PK Sim Identificador único de cada item registrado no pedido.
quantidade INT - Sim Quantidade do produto incluída no pedido.
preco_praticado DECIMAL(10,2) - Sim Preço aplicado no momento da venda, permitindo registrar promoções ou alterações de valor.
id_pedido INT FK Sim Identifica o pedido ao qual o item pertence.
id_produto INT FK Sim Identifica o produto incluído no pedido.

Entidade: Pagamento

Atributo Tipo sugerido Chave Obrigatório Descrição
id_pagamento INT PK Sim Identificador único do pagamento.
forma VARCHAR(40) - Sim Forma de pagamento utilizada, como dinheiro, Pix, cartão de débito ou cartão de crédito.
valor DECIMAL(10,2) - Sim Valor pago pelo cliente.
status VARCHAR(30) - Sim Situação do pagamento, como pendente, aprovado, recusado ou estornado.
id_pedido INT FK Sim Identifica o pedido relacionado ao pagamento.

Entidade: Plataforma

Atributo Tipo sugerido Chave Obrigatório Descrição
id_plataforma INT PK Sim Identificador único da plataforma parceira.
nome VARCHAR(60) - Sim Nome da plataforma utilizada para venda, como iFood ou Keeta.

Regras Gerais

Observação importante: WhatsApp não é considerado plataforma no modelo. Ele funciona como canal de pedido ou forma de compra direta.

Plataformas: iFood e Keeta representam serviços externos de venda e devem ser tratados na entidade Plataforma.

Pedido e produto: Um pedido pode possuir vários produtos, e essa relação é registrada por meio da entidade Item_Pedido.

Preço praticado: O campo preco_praticado registra o valor no momento da venda, mesmo que o preço padrão do produto mude depois.
